# Profile MVP 修改计划（临时版）

状态：已实施。本文保留为 Profile MVP 的需求与验收记录；后续移动端工作以 `IOS_LOCAL_DEVICE_MVP_PLAN.md` 为准。

## 目标与阶段划分

MVP 采用“本地衣橱 + 云端账户资料”。Supabase 负责邮箱登录、名字和头像；衣物、衣物图片和搭配保存在本地。

云端衣橱上传与恢复留到第二阶段，MVP 不显示相关入口。保留 Import / Export 作为手动备份方式。

## Profile 与个人资料

- 只保留一个默认头像：现在的小猫。不提供其他预设头像选项，用户可以上传自己的照片。删除整个 Personalize 菜单。
- 点击主页面头像可选择本地照片，默认居中裁成正方形，支持调整位置、缩放和预览；确认保存，取消不改变原头像。
- Information 复用现有卡片样式，包含 Name、只读 Email address、Change your avatar、Save information。
- 删除 Member since 和 Information 中原有的数据存储说明。
- 在 Information 中选择并裁剪照片后，先显示新头像供用户预览；点击 Save information 才一起保存名字和头像。如果未保存就关闭卡片，原来的名字和头像保持不变。界面不出现“草稿”一词。
- 新账户首次验证成功后自动打开 Information；名字需要填写，头像可以保持默认。保存后记录资料设置已完成，后续登录不重复弹出。
- 首次设置被关闭时不阻止使用，下次登录继续提示；现有账户不强制重新设置。
- 头像作为账户资料上传至私有文件存储；只保存裁剪压缩后的图片，不上传原始照片。上传失败保留旧头像及当前编辑内容。
- 本次不实现修改邮箱。

## 游客、登录与本地数据

- 游客可添加、查看、编辑、删除衣物，可使用搭配编辑器；保存 Outfit 时提示登录并保留当前编辑内容。
- 游客不能修改账户名字、头像，不能使用 Import / Export；相关入口显示登录提示。
- Settings 对游客开放，排查并修复游客无法打开的问题。
- 登录用户可以保存 Outfit，并使用 Import / Export。
- 关闭页面、关闭 App、重启设备或 Log out 均不主动删除本地衣橱。
- Log out 后回到游客状态，不展示原账户衣物；同设备重新登录同一账户直接读取本地数据。
- 保留底层按账户 ID 区分数据的机制，界面不解释多账户分区。
- 登录后检测到游客衣物时，提示“加入／跳过”。加入将衣物归入当前账户；跳过后再次明确确认删除，取消确认则返回选择。删除完成前不丢弃游客数据。
- 删除 Settings 中的游客衣橱迁移入口。
- 本地数据仍可能因清除网站数据、删除 App 或系统存储行为而丢失，账户登录不能恢复未备份的衣橱。

## Settings、接口与实施顺序

- 保留 Export / Import 原名称，仅登录用户可用。Export 包含当前衣橱的衣物资料、图片和已保存搭配；Import 接受应用导出的 ZIP，追加导入，不覆盖已有内容，重复导入会产生副本。
- 保留现有 ZIP 格式及 100 MB 限制，导入前显示内容数量及重复导入提示。
- 删除 Settings 中用户指出的长段存储说明，必要说明放在对应操作的确认界面。
- Clear 仅清空当前本地衣橱，不删除账户；确认文案清楚说明不可撤销。
- Logout 文案说明本地数据保留，不询问云端上传，不清空衣橱。
- 保留独立的 Delete account 功能及身份验证；删除账户时同时清理云端头像和当前设备该账户的本地数据。

实施时扩展个人资料类型及接口，增加自定义头像引用和首次资料设置完成标记。未上传照片的用户统一使用小猫默认头像；之前选过其他预设头像的账户，也统一改为小猫，并更新对应的本地资料缓存。已保存的名字和本地衣橱不受影响。

增加受登录保护的头像上传能力及存储权限配置，文件只能由所属账户管理。

按以下顺序实施：资料与头像存储迁移 → Information 和头像交互 → 首次注册流程 → 游客功能限制与迁移提示 → Settings 文案及回归验证。更新部署文档，明确新增 Supabase 存储配置；衣橱云端备份不在本次实现中。

## 验收与第二阶段

验收覆盖：

- 新用户首次填写资料、老用户编辑资料、唯一的小猫默认头像、自定义头像裁剪、取消及上传失败。
- Information 中未保存就关闭时不修改资料，点击 Save information 后名字和头像正确保存。
- 旧预设头像统一回退为小猫，名字和本地衣橱不受影响。
- 游客可打开 Settings、管理衣物；保存 Outfit 和 Import / Export 正确要求登录。
- 登录过程中搭配编辑内容不丢失；游客衣物加入或确认删除行为正确。
- 关闭后数据仍在；退出后不可见，重新登录同账户恢复本地显示。
- Clear、Delete account、Import / Export 行为不混淆，旧 ZIP 和现有本地数据兼容。
- 不同账户无法通过接口读取或修改他人的头像。
- 类型检查、Lint、相关单元测试和浏览器流程测试通过。

第二阶段加入登录后手动操作的“上传备份”“恢复备份”。登录本身不下载衣橱，恢复必须由用户主动触发；具体容量、费用、覆盖规则和失败恢复机制届时单独确认。
